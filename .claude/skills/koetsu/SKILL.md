# /koetsu — 独立校閲（逐語録忠実性チェック）

対象: $ARGUMENTS

## 原則（これだけ）
**基本は『逐語録への忠実性』。ただし逐語録に明白な誤りがある場合、誤りをそのまま載せない。**
記事の読者は大半が動画を見ていない。記事“単体”で見て破綻していると媒体の信頼が落ちるため、
明白な誤り（言い間違い・モデル名の取り違え・誤変換）は下の4分類で処理する。
**推測の“正解”で上書きしてはならない**（それ自体が新たなハルシネーション）。

採点軸は2つだが独立に扱う：①**逐語録に忠実か**（主軸）②**世界の事実として明白におかしくないか**
（“おかしさセンサー”としてのみ使う／全件の裏取りはしない）。

## 独立性
執筆ドラフトの説明・推論・コメントを **無条件に信用しない**。ドラフトが「〜と確認済み」と書いていても、
逐語録と用語集で自分で突き合わせ直す。読み取れない箇所・開けない資料は「未確認」と明示する。

## 入力
- 対象記事（`src/content/episodes/<slug>.md` または公開URL）。URLなら実ページも取得する。
- **逐語録**（kirinuki Whisper の文字起こし。唯一の原典）。渡されなければ在りかを尋ねる。
- **用語集** `editorial/glossary.md`（固有名詞の正規表記＋ as-of 正式名称）。

## チェック（優先順）
1. **逐語録照合**：記事の各主張が逐語録のどこに対応するか確認。
   - 逐語録に無いこと（SEO的な作文・一般論の水増し・勝手な枠組み）→ 検知。
   - 取り違え（別モデルの数値が移っている／2モデルを1行に合体している 等）→ 検知。
   - 条件付き発言から条件が落ちていないか、登壇者の見解が客観的事実に格上げされていないか。
   - **比較表は行ごと**に逐語録へ対応付ける（セル単位でモデル・指標・単位・条件を保つ）。
2. **用語集照合**：固有名詞・モデル名・バージョンを `editorial/glossary.md` と突合。
   - **英語の固有名詞（AIモデル名・企業名・サービス名）がカタカナのままになっていないか**を確認し、英語表記へ直す（例：メタ→Meta、オパス→Opus）。普通名詞のカタカナ語は対象外。
   - as-of に無い版（例 `Claude 3.5 Opus` `Fable 5.1`）は非実在の疑い → 検知。
   - `Fable` 自体は実在（Fable 5）。版だけ誤りなら版を外す等、過剰に消さない。
3. **誤字・明白な数値ミス**：誤変換（例 `重量課金`→`従量課金`）、桁・単位・計算の明白な誤り。

## 検知後の4分類（＝出力の指示）
| 状態 | 扱い | 例 |
|---|---|---|
| 誤変換・言い間違いで意図が自明 | **直す** | 重量課金 → 従量課金 |
| 固有名詞/モデル名が明白に誤り・正解は不確実 | **ぼかす**（一段上の概念へ一般化。読者向け注記は付けない） | Claude 3.5 Opus / Fable 5.1 → Anthropicの最上位モデル |
| 数値等が非現実的で意図も不明 | **要確認**（人へ通知） | 桁がおかしい料金・比率 |
| 逐語録に無い | **削除** | 水増しの枠組み |

ぼかしを基本にする。具体の正解は **逐語録＋用語集で高確度に取れる時だけ** 差し替える。
数値（例「約205円」）が登壇者の検証結果なら、消さず **「動画内の検証では約205円」と帰属付けて残す**。

## 本文はクリーンに、不確実は“通知”で（重要）
- **記事本文に読者向けの不確実性ヘッジを書き込まない**：「（動画内での呼称）」「動画内で示された」
  「正式名称と異なる場合があります」等は**入れない**。ぼかす時も言い切った一般名詞にし、注記を付けない。
  ※話者への帰属（「佐藤氏は〜と述べる」）はヘッジではないのでOK。
- **危うい・確認が要る箇所は、記事ではなく“校閲レポート（この実行の返り値）”で人へ通知する**。
  記事化パイプラインでは、この返り値が人への通知になる。下の出力で必ず出すこと。

## 出力（日本語・短く）
1. 1行サマリ：対象 / 公開判定（**PASS**＝未解決の要修正なし ／ **HOLD**＝要修正or重大な要確認が残る）。
2. 件数：総主張数・逐語録で確認できた数・要修正・要確認・任意。実数のみ（「一部だけ見て完了」を防ぐ）。
3. トリアージ一覧：各項目に **[要修正/要確認/任意]** ・場所・原文・問題・逐語録の対応箇所・推奨（直す/ぼかす/要確認/削除）。重大順。
   - レポート体の長文は書かない。人が見るのはこの一覧と【要確認】だけで済むようにする。
4. **⚠ 要確認・要検証の通知**：固有名詞・新モデル名・社名・綴り・数値など「間違いが危うい／外部確認が要る」
   箇所は、本文をクリーンにしたうえで**この一覧に必ず挙げる**（場所・なぜ危ういか・何を確認すべきか）。
   ＝記事化時に人へ渡す通知。本文にヘッジを残す代わりに、ここで知らせる。

## --apply
`--apply` 指定時のみ、**4分類のうち「直す」（自明な誤字・誤変換）と、ぼかしで確実なもの**をローカルで適用する。
判断が難しい箇所は変更せず **本文に `【要確認: …】` を残す**。コミット・push・公開はしない。
修正後は、その箇所をもう一度逐語録と突き合わせて再確認する（新しい事実を足さない）。
